# 云台跟随装甲板：闭环自瞄逻辑

本文说明「云台跟随装甲板」这一小部分的代码位置与运行逻辑，重点讲清楚闭环坐标变换的推导、符号约定，以及曾经导致云台不停转圈的根因与修正。

## 一、涉及的代码

| 文件 | 职责 |
|------|------|
| `src/traditional_detector.cpp` | 传统装甲识别：HSV 分割 → 灯条配对 → 输出装甲板四角点 |
| `src/auto_aim_node.cpp` | 主控节点：订阅图像/相机内参/云台反馈，调解算器，发布 `gimbal_cmd` |
| `src/closed_loop_solver.cpp` | **跟随核心**：PnP + 坐标变换 + 一阶低通滤波 + 限幅 |
| `include/auto_aim/closed_loop_solver.hpp` | 解算器接口与 `Result` 结构 |
| `src/serial_node.cpp` | 串口收发：下发期望角给电控、收 IMU 四元数并解出 yaw/pitch |
| `msg/GimbalCmd.msg` / `msg/GimbalFeedback.msg` | 下发/反馈消息定义 |

## 二、整体数据流（闭环）

```
相机 image_raw ─► traditional_detector.detect() ─► 装甲四角点 points
                                                        │
        ┌───────────────────────────────────────────────┘
        ▼
AutoAimNode::imageCallback  (src/auto_aim_node.cpp)
  ① 取第一个装甲目标 + 判 IMU 新鲜度
  ② closed_loop_.aim(armor_valid, imu_valid, points, type, gimbal_yaw, gimbal_pitch)
        ▼
ClosedLoopSolver::aim  (src/closed_loop_solver.cpp)   ★跟随核心
  ③ PnP → Pc(相机系)
  ④ 坐标变换 Pc → Pworld(世界/基座系)
  ⑤ atan2 求目标 yaw/pitch → 低通滤波 → 限幅
        ▼
latest_cmd_ 发布 "gimbal_cmd"
        ▼
SerialNode::cmdCallback  (src/serial_node.cpp)
  ⑥ control=true 才下发 → 串口 → 电控转动云台
        │
        └──► 电控回传 IMU 四元数 ─► quat_to_yaw_pitch ─► 发布 "gimbal_feedback"
                                              │
                                              └──► 回到 AutoAimNode 作为下一帧的 gimbal_yaw/pitch
```

## 三、核心：闭环坐标变换（ClosedLoopSolver）

### 坐标系定义

- **相机系 C**（OpenCV）：光心原点，X 右、Y 下、Z 前。
- **世界系 W**（云台基座/零位）：X 前、Y 右、Z 上。
- 云台命令角约定：**yaw 向右为正、pitch 向上为正**（rad），下发值是相对云台零位的期望角。
- 装甲板对象系：X 右、Y 下、Z 面朝相机；四角点顺序 `[左上, 右上, 右下, 左下]`。

### 五步处理（`ClosedLoopSolver::aim`）

1. **保护**：装甲丢失 / IMU 失效 / 相机未标定 / 点数 ≠ 4，任一不满足则复位滤波、输出 `control=false`（停发不跟随）。

2. **PnP**：用装甲物理尺寸（`small_armor_width` / `lightbar_length`）构造 3D 模型点，`cv::solvePnP(..., SOLVEPNP_IPPE)` 求目标在相机系的平移 `tvec` → `p_cam`。

3. **坐标变换（相机系 → 世界系）**，关键在旋转矩阵的构造：
   ```
   P_world = R_C2W · P_cam
   R_C2W   = R_z(-yaw) · R_y(+pitch) · R0
   ```
   - `R0`：零位时相机轴到世界轴的固定排列
     ```
     R0 = [[0, 0, 1],     # 相机 Z 前 → 世界 X 前
           [1, 0, 0],     # 相机 X 右 → 世界 Y 右
           [0,-1, 0]]     # 相机 Y 下 → 世界 -Z（即上）
     ```
   - `Rz`、`Ry`：绕世界 Z/Y 轴的旋转，`yaw`、`pitch` 用云台当前反馈角。

4. **atan2 求目标角**：
   ```
   yaw_raw   = atan2(yw, xw)
   pitch_raw = atan2(zw, hypot(xw, yw))
   ```

5. **滤波 + 限幅**：一阶低通 `filt = alpha·raw + (1-alpha)·filt`，再 `clamp` 到 `±angle_limit`；`valid=true, control=true`。

### 关键坑：IMU 四元数给的是 world→camera，必须取反

> 这是「云台不停转圈」的根因，已在 `src/closed_loop_solver.cpp` 修正。

反馈的 yaw/pitch 不是云台电机角，而是从 IMU 四元数解出来的姿态角。四元数 `q` 表示 **世界系 → 机体（相机）系** 的旋转 `R_world→camera`。用 Z-Y-X 欧拉分解（`serial_node.cpp` 的 `quat_to_yaw_pitch`）：

- 云台向右转 `+φ` 时，`R_world→camera = Rz(-φ)`，解出的 `yaw = -φ`。
- 同理 pitch 解出的是 `-θ`。

所以 `yaw_fb = -φ`、`pitch_fb = -θ`，与命令角（右正/上正）互为相反数。若直接拿去构造 `Rz(yaw_fb)·Ry(-pitch_fb)`，等于把相机朝向的旋转**反着用**：

```
错误：R_C2W = Rz(yaw_fb)·Ry(-pitch_fb)·R0 = Rz(-φ)·Ry(+θ)·R0   ← 逆旋转，正反馈 → 转圈
正确：R_C2W = Rz(-yaw_fb)·Ry(+pitch_fb)·R0 = Rz(+φ)·Ry(-θ)·R0   ← camera→world
```

修正后的代码（`closed_loop_solver.cpp:83-84`）：

```cpp
double cy = std::cos(-gimbal_yaw), sy = std::sin(-gimbal_yaw);   // 取反
double cp = std::cos(gimbal_pitch), sp = std::sin(gimbal_pitch); // 取反（原为 -pitch）
```

对单轴旋转，求逆 = 转置 = 角度取负，即「取逆旋转」。修正后闭环收敛：目标静止时解出的命令角为恒定目标方位，与云台当前角无关，云台转到该角后停住。

## 四、下发与跟随规则

- `auto_aim_node.cpp` 把 `Result` 填进 `GimbalCmd`：`control = res.control`，`yaw/pitch` 用解算结果；速度/角速度当前置 0（无 EKF/预测）。
- `serial_node.cpp` 的 `cmdCallback`：`control=true` 才持续下发 = 跟随；`false` 停发 = 不跟随。
- 串口帧 `AimbotFrame`（ID=0x02）：`PitchRelativeAngle` / `YawRelativeAngle` 为期望角（rad），正 yaw 向右、正 pitch 向上。

## 五、调试 / 验证

`config/auto_aim.yaml` 里 `closed_loop_debug: true` 会打印：

```
[closed_loop] tvec=(..) gimbal=(..) world=(..) raw=(..) -> filt=(..)
```

- 目标静止时，`raw` 应稳定为常数、云台收敛后停住。
- 若云台**反向**转（或 pitch 反向），说明 IMU 安装朝向把符号翻到了另一边，把 `closed_loop_solver.cpp:83-84` 两个负号整体对调即可；判定标准是「`raw` 恒定 + 云台收敛到该角不动」。
